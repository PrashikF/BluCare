Technical Component Breakdown

Frontend

  • Tech Stack: HTML5, CSS3, Vanilla JS
  • State Management: Maintains unique session ID for stateful chats.
  • Geolocation: Captures user's Latitude & Longitude on load and appends it as `[SYSTEM CONTEXT]` to messages.
  • Dynamic UI: Parses Markdown from the backend, including actionable buttons (e.g., `[ACTION:Find nearby hospitals...]`).

API & State Persistence

  • Tech Stack: FastAPI, Uvicorn, SQLite
  • Lifespan Hooks: Warms up Qdrant client, HF Embeddings, and Cross-Encoder at startup to prevent cold-start latency.
  • Checkpointer: Utilizes LangGraph `SqliteSaver` (with Redis fallback) to persist the `TriageState` seamlessly across HTTP requests.

LangGraph Multi-Agent Workflows

1. Central Agent (The Router)

Uses a LLaMA 3.1 70B model with strict structured output. Forces 3-5 clarifying turns to gather symptoms before routing. Employs a rolling summary (via 8B model) to manage context limits. Routes to RAG, Synthesis, Remedy, or Facilities based on intent.

2. Distillation & Synthesis

Distillation: Uses a fast LLaMA 8B model to strip medical noise from RAG chunks, saving massive tokens.
Synthesis: Diagnoses the condition, lists alternative causes, and generates Markdown with action buttons.

3. Remedy Agent

If requested post-diagnosis, retrieves targeted Ayurvedic herbs and OTC options from Qdrant, strictly formatting reasons why they help and listing red flags.

4. Facilities Agent

Triggers a tool-calling LLM to execute a Selenium web scraper. It passes the user's GPS coords to Google Maps, extracts top 5 hospitals/ambulances, and returns formatted links.

Advanced RAG Pipeline

  1. Self-Query Constructor: LLM translates natural language into Qdrant metadata filters (e.g. detecting "Ayurvedic intent").
  2. Dense Retrieval: BGE embeddings search Qdrant with a strict score threshold to prevent hallucinated matches.
  3. MMR (Maximal Marginal Relevance): Diversifies the candidate pool so chunks aren't perfectly redundant.
  4. Cross-Encoder Reranking: Uses `sentence_transformers` to score the Query-Document pairs, ensuring ultimate precision before passing context to the LLM.
